LoRA: masalah dan ide

Masalah: full fine-tuning memperbarui semua parameter. Memori besar (bobot + gradien + optimizer states Adam, sekitar 3–4× ukuran model), dan setiap tugas butuh satu salinan model penuh.

Ide: perubahan bobot saat adaptasi (ΔW) punya rank rendah. Bekukan W₀, lalu latih dua matriks kecil: ΔW = B·A, B ∈ ℝd×r, A ∈ ℝr×k, r ≪ min(d,k).
Detail yang bagus ditulis di jawaban
  • B diinisialisasi nol, jadi di awal ΔW = 0 (model mulai persis dari model asli).
  • Bisa di-merge: W = W₀ + BA, sehingga tidak ada latensi inferensi tambahan.
  • Satu model dasar, banyak adapter kecil (satu per tugas).

Coba sendiri: berapa parameter yang dilatih?

Satu matriks bobot berukuran d × d. Geser rank r dan lihat bedanya.

Full fine-tuning: parameter

LoRA (r·(d+k)): parameter, yaitu dari full

QLoRA: masalah dan ide

Masalah: LoRA mengurangi memori training, tetapi bobot model dasar masih disimpan 16-bit. Model 65B ≈ 130 GB hanya untuk bobot, tidak muat di satu GPU biasa.

Ide: simpan model dasar dalam 4-bit (dibekukan), latih hanya adapter LoRA 16-bit. Hasilnya: model 65B bisa di-fine-tune di satu GPU 48 GB.
TrikFungsi
NF4 (4-bit NormalFloat)Tipe data 4-bit yang dirancang untuk bobot yang berdistribusi normal.
Double quantizationKonstanta kuantisasi ikut dikuantisasi untuk menghemat memori.
Paged optimizersMemakai memori CPU saat GPU hampir penuh, mencegah out-of-memory.

Kritis: bobot 4-bit tidak dilatih. Saat forward/backward, bobot di-dequantize ke BF16, dan gradien hanya mengalir ke adapter. Trade-off: training lebih lambat dan ada sedikit kehilangan presisi.

Catatan kritis
